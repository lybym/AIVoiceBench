| 1.5.11 | 2026-09-19 | 落实 F013/F014 的证据工作台与按 revision 产出的报告（Issue #11）。新增 `aivoicebench/workbench.py` 作为唯一投影点：把当前 AnalysisRevision 的持久化文档投影为 `tracks`/`regions`/`metrics`/`findings`/`unavailable`/`abstentions`/`evidence_integrity`/`provenance`，经 `GET /api/runs/{run_id}/evidence-workbench` 与 `AnalysisResponse.workbench` 发布。Region 坐标直接取自持久化 acoustic/speaker/turn/event 区间；metric/finding 取其自身引用证据的包络（`evidence_ids` → `event_ids` → `turn_ids` 固定优先级）并标注 `envelope_of`，浏览器不重新计算指标或事件。**证据边界**：(a) 转写行到 Region 的关联由后端从 fused segment 的 `asr_segment_id`→`acoustic_segment_id` 交叉引用解析并作为 `region_id` 发布——ASR utterance id 与声学片段 id 是互相独立的命名空间，前端不得按命名约定猜 id，一个 utterance 对应多个声学片段时发布候选并保持不可点击；该交叉引用只保证“同一段音频”而非“区间相等”，故同时发布 `region_basis` 与 `region_span_matches`，容器区间必须如实标注为容器；(b) 被消费文档（含 `audio-metadata.json`）存在却无法解析时，投影给出 `status: unreadable` 条目并置 `evidence_integrity.status = incomplete`，损坏证据不与“该阶段没有证据”同形；(c) 同一文档内重复记录 id 不抛出，重复项作为 `status: invalid` 缺口进入 `unavailable`/`abstentions.skipped_records`，一条脏记录不得让整个 revision 不可复核；(d) 记录声明却无法解析的引用进入 `abstentions.unresolved_references`，并用 `cause` 区分 `not_declared` 与 `no_interval`；(e) `unavailable` 条目标注 `not_run` 与 `incomplete`/`failed`，`abstentions.stages` 只含后者；(f) `region.source.processor` 取自发布该文档的 artifact（stage envelope 按 schema 不含 `processor`）；(g) `GET /api/runs/{run_id}/evidence-workbench` 为三态契约：Run/Revision 缺席 → 404，证据存在但投影失败 → 500（不得折叠为 404），投影成功 → 200 并自带全部缺口。角色确认未完成时 role-dependent 轨道不发布并在 `unavailable` 说明原因，其解析区间仅以 `resolved_span` 供审计，工作台只呈现显式 provisional 视图。报告改为按 AnalysisRevision 产出 `report.json`/`report.md`，新增证据分级（deterministic / semantic / human_reviewed）、证据索引、指标结果（未观测值渲染为 abstained，不填 0）、未完成/失败/弃权阶段（含 `not_run` 与 `incomplete`/`failed` 类别）、`evidence_integrity` 与 provenance；报告不再把自己登记为证据，因此对同一 revision 重新生成字节一致，且新 revision 不覆盖旧 revision 的报告。前端以 wavesurfer.js 7.12.12（同源 `/static/vendor/`，记录版本与逐文件 SHA256）实现 waveform + Regions + Timeline 与 Finding/Metric/Event 定位；`scripts/verify-workbench-render.mjs` 接入 `npm run verify`，并支持 `--document` 用真实 `build_workbench()` 输出复跑渲染不变量。#11 软件验收完成；Docker/远端 Chrome 实机与真实录音复核仍由 #85 承载。 |
