| 1.5.14 | 2026-09-20 | 落实 v0.6.0-rc.3 端到端测试（[#113](https://github.com/lybym/AIVoiceBench/issues/113)）记录的三项产品行为修正。**本版不新增验收门槛，也不放宽任何既有守卫。** (a) **人工角色确认保存是异步操作（F012/F017）。** 真实录音上该重建约 12 `<output_root>/.role-review-operations/<run_id>/OP-*.json`（与 Run 证据链分离，因为 Run 树内文件会被登记为不可变保留诊断），因此重试与重启后的服务都能回答这次重建的身份、阶段与终态，而不会隐式提交第二次重建。拒绝以 `detail.code` 区分并带 `retryable`：`run_locked`(409)、`operation_in_progress`(409，附在跑的 `operation_id`)、`insufficient_evidence`(422)、`internal_error`(500)，另有 `invalid_request`/`forbidden_origin`/`payload_too_large`/`legacy_analysis`。`GET .../role-review/operations[/{operation_id}]` 发布 `status`/`phase`/`phases`/`elapsed_ms`/`heartbeat_at`/`stalled`/`error`/`result`；阶段名取自重建真实经过的阶段。心跳停滞是**待决状态**（`stalled: true` 仍可查询），只有操作者显式重新提交才记为 `interrupted`。每次重建按事件写一行结构化日志（`run_id`/`analysis_id`/`operation_id`/`phase`/`elapsed_ms`/`error_code`），只含分类与标识，从不回显异常原文或凭据。(b) **Free 模式每轮推进有界且可解释（F021/F023）。** 采集结果由音频 socket 发布、控制 socket 消费，二者独立：页面此前在采集开始时就 armed 15 s 结果等待，设备回答较慢时该等待提前作废，随后控制侧 `capture_result` 早于服务端 finalisation 到达，被当作"没有已完成的采集"忽略，轮次停死且无可见原因。现在页面只在发送 `capture_stopped` 后计时；服务端在结果尚未发布时**有界等待**在飞的 finalisation（`no_response_timeout_ms` + 5 s）并记录 `capture_result_waited`；超过上限则记录 `capture_result_wait_timeout`、以 `capture_finalisation_timeout` 显式失败并关闭该轮（**不记为回答完成**）。`GET /api/voice-test/sessions/{id}` 新增 `progress`（`phase`/`reason_code`/`turn_id`），其中 `capture_finalised` + `capture_finalised_awaiting_control_result` 就是此前不可见的状态；网页在运行期间轮询并显示非等待类阶段与原因。(c) **分析页统计口径与完成语义分列（F013/F014）。** 聚类数只按 `speaker_id` 去重计数（此前把 diarization 文档条目数当聚类数，5 聚类 65 片段的录音显示成 65 个聚类）；`complete_review` 只表示人工角色决策完成，不再被呈现为"指标将完整生成"的承诺，指标为空的真实原因（`unknown` 聚类、未匹配片段、空时间线）与"弃权不等于设备未通过"单列陈述。**证据边界**：本次全部为 software_verified（fixture/脚本化 transport/真实浏览器/API），未使用真实录音、未做真实云调用、未做实体设备验证；真实录音人工标注与端到端验收仍由 [#85](https://github.com/lybym/AIVoiceBench/issues/85) 承载。 | 1.5.13 | 2026-09-19 | 落实 N001–N007 的 M1 真实录音验收证据契约与 Gate 检查器（Issue #85）。新增 `AcceptanceRecord 1.0.0`（`schemas/acceptance-evidence.schema.json`）、确定性检查器 `aivoicebench/acceptance_evidence.py` 与 CLI `aivoicebench acceptance init|check`。**本版不新增或降低任何产品要求，也不改变任何验收门槛**：它把 #85 已声明的门槛变成可执行校验。(a) **未授权输入不能被写成已验证。** `real_recording_verified` 只在存在 `authorized_real_recording`/`authorized_field_recording` 样本、时长落在授权 5–20 分钟区间内、人工复核证据与 machine originals 分离存在、声明的 artifact 与 evidence 摘要经 `--verify-artifacts` 实际重算匹配、且 `--repository-root` 指向的仓库目录被真实遍历且未发现 Git 内音频时才成立；因此产生绿色结论的调用为 `acceptance check <record> --verify-artifacts --repository-root <repo>`。synthetic/fixture 样本、`synthetic_fixture`/`ci_run` 证据、机器生成却被记为人工的标注，都会被判为 **unauthorized claim**（记录 `status: invalid`），不得作为通过。**未执行的对照不得被报告为已执行**：未请求校验、未提供仓库根、仓库根不存在或不是目录、或记录声明的 `exposure_scan.scan_roots` 条目无法遍历时，该 gate 不予授权，CLI 也不会以 0 退出（结果同时给出 `repository_scanned`/`repository_root`/`repository_files_inspected`/`unchecked_scan_roots`）。真实云 Gate 必须有以显式 `sample_id` 绑定到**授权真实样本**的 `real_cloud_invocation`（路径子串不算绑定，synthetic 样本不得授权该 gate）；脚本化 transport/mock 不算云调用；授权真实 gate 的 evidence 与每个 stage 分母的 evidence 都必须解析到本地真实存在的 Artifact 且摘要匹配。(b) **结论必须可回溯。** 每条 traceability chain 必须有 Run、音频区间、至少一个**在记录内唯一声明**的 evidence id 与 processor/model/policy version；缺 Turn/Event 或缺失效版本作为显式 blocking gap 报出（PRD-N001）。(c) **分母不得只报成功。** 每个 stage 的 counters 必须含 complete/partial/failed/unknown/abstained/not_applicable 且其和等于 `expected_total`（PRD-N007）；**任何**已声明的 evaluation（含 `failed`/`abstained`/`not_attempted`）都必须有其 stage 的分母；声明真实录音 Gate 的记录必须覆盖 M1 全部 stage（`not_applicable` 为有效答案），整体缺席的 stage 视为按省略构成的 success-only 分母，且不得提交空 evaluations。(d) **人工层独立且受校验。** 人工复核必须与 machine original 分离（PRD-N002），不得 derived from machine outputs、不得与机器产物同 digest，且其 artifact 与样本 artifact 同样必须通过摘要重算；角色修改必须生成新 AnalysisRevision、保留旧结果字节、给出 recompute 与 diff 证据，且 `recompute_scope` 不得为 `recomputed_recognition`（人工角色决定不得重跑识别/聚类）。(e) **不得提交私密材料。** 检查器扫描 credential-shaped 值/私密字段、PEM 私钥、signed URL 与 Git 内音频，只报告位置、不回显内容（PRD-N004）；真实录音、转写与生成报告必须留在 Git 外。(f) **blocking 与 observation 分离。** 记录级 blocking gap（未校验的 artifact/evidence、未遍历的仓库或 scan root、未绑定的复核、缺会话单元或版本、缺 stage 分母、不干净扫描）未清零时记录不得判为 `complete`；仅陈述事实的 observation（如“该样本是 synthetic”）不单独阻断。(g) **状态语言。** 记录必须逐 gate 状态化（`software_verified`/`container_verified`/`browser_verified`/`real_cloud_verified`/`real_recording_verified`），未达到的 gate 必须写明缺口；CLI 退出码 0 = 全部 gate 已验证并授权且无 blocking gap、2 = 记录自洽但真实录音 Gate 仍未完成、1 = 存在未授权声明或记录不合法。该检查器只能证明声明摘要与本地文件一致、声明之间互相授权，**不能证明某个声明样本确实是授权真实录音**。(h) **声明的数值与控制必须对账，不得只声明不核对。** 样本 artifact 声明的 `byte_length` 必须与保留文件的实际字节数一致（不一致为 error），授权真实样本的 audio artifact 必须声明 `byte_length`（缺省为 blocking gap）；两个样本声明同一 `sha256`（同一物理文件被计为两条“不同”录音）或同一样本内重复声明同一摘要均为 error，因为授权样本数是被报告的结果、不得被重复引用放大；五个 gate 中标为 `verified` 者必须带 `verified_at` 时间戳。(i) **声明值与测量值必须可区分。** 5–20 分钟区间由样本自报的 `duration_ms` 判定，检查器不解码音频，因此结果新增 `declared_only_controls`（Markdown 报告为 “Conditions checked against declared values”）逐项列出只与记录自身对账的条件（区间、`source`/`device`/`authorization`、未提供仓库根时的 `exposure_scan.clean`），不得据此声称检查器测量过录音。(j) **未覆盖必须报出，不得当作干净。** 暴露扫描改为读取被遍历根下每个可解码为文本的文件，无法解码的文件进入 `repository_files_unread` 而不是静默计为已检查，同一个根被重复声明时只遍历一次，使 `repository_files_inspected` 不再被重复计数放大。扫描的**全部**排除项都被披露：定义/验证检测模式本身的策略源码作为 `detection_policy_sources_skipped` 报出且按**仓库相对路径**而非 basename 匹配（同名文件位于其他位置仍会被扫描）；不做降级遍历的环境与构建目录（`dist`/`build`/`node_modules`/`.git`/`.venv`/`__pycache__`/缓存目录等）逐条记入 `repository_directories_skipped` 并写入 Markdown 报告，其内容不在覆盖范围内——"clean" 不得表示"没有看过"。(k) **真实录音 gate 的人工层证据必须是记录自身声明的人工复核 artifact。** gate 上的 `human_review` 证据除 `kind` 与显式 `sample_id` 绑定外，其摘要必须等于某条 `human_reviews[].artifact.sha256`（缺摘要同样不予授权），否则判为未授权声明——否则任一本摘要自洽的本地文件即可承载整条真实录音声明，而记录声明的 `human_reviews[]` 指向别处（PRD-N002）。(l) **人工复核层适用与样本层相同的摘要唯一性。** 同一条标注 artifact 被两条不同复核复用判为 error，并新增 `human_review_count` 使人工层规模可审计。(n) **记录自报的 exposure finding 与分母都不得与记录自身的其他声明矛盾。** `exposure_scan.findings` 此前从未被读取：一份既记录 `real_recording_in_git` 又声明 `clean: true` 的记录仍被判 `complete` + `real_recording_verified=True` + 0 error/0 gap——即用 PRD-N004 这条 gate 所要拒绝的条件去授权该 gate。现在记录自报的任何 finding 都使记录不得作为验收证据，`clean: true` 的唯一形态是 `findings` 为空（检查器自扫结果与记录自报结果同等处理）。同理，`measured` 的 evaluation 其 stage 的 `expected_total` 不得为 0：把 15 个 stage 全部报成空分母虽然「交代了每个 stage」，却一条失败/未知/弃权都没计入，属 AC3 禁止的形态；非 `measured` 状态允许 0 记录。(o) **验证时间必须可重建，且该对照 fail-closed。** `recorded_at`/`verified_at`/`authorization.authorized_at`/`annotated_at` 在 schema 中声明为 `date-time`：无法解析的时间戳在契约层被拒，而不是让时序对照静默跳过。时间轴顺序为 授权 `authorized_at` ≤ 复核 `annotated_at` ≤ gate `verified_at` ≤ `recorded_at`；任一环节缺失或不可解析均为 error，授权样本未声明授权时间时该 gate 不予授权（此前的实现以 `authorized_at is not None` 守卫，因此把该可选字段置空即可让整条对照静默失效而 gate `byte_length`」。(m) **声明的录音参数与声明的 artifact 尺寸必须算术自洽，且该对照是否行使必须具名披露。** 对未被压缩的 raw PCM 编码，`duration_ms × sample_rate_hz × channels × 每样本字节数` 即为 artifact 应有大小，与 `byte_length` 不符（1 ms 容差）判为 error：否则 48 字节的文件同样可以声明为 8 分钟 16 kHz 单声道 PCM 而通过。对 mp3/m4a/opus 等压缩或容器格式不发明尺寸算术，只做文件尺寸对账。由于 `encoding` 为自由文本、未识别拼写（如 `wav`）或压缩编码会使该对照不适用，结果给出 `audio_size_arithmetic_applied` / 保持"尚未通过"，本版不产生任何真实录音证据，#85 保持 Open。 |
