# AIVoiceBench v0.4.0-alpha.3

**这是一个预览版（Pre-release），不是完整 M1/M2/M3 交付。** 本版是 `v0.4.0-alpha.2`
之后的**集成与候选制品一致性**修复版：把此前只存在于本地分支（原修复提交 `6c34c74`）
的语音测试修复，重新表达并集成到 Streaming ASR 架构之上，并让**每一个模式在启动前
真正被后端预检门禁**约束。

`v0.4.0-alpha.2` 镜像**不包含**这些修复，本版镜像包含。判定依据不是版本号、不是镜像
构建成功、也不是 `/health`，而是候选镜像内运行的目标行为用例（见“已验证范围”）。

本版没有完成真实云或实体设备验收。未配置云服务时，录音导入与本地分析能力仍可使用；
主动测试中的 Fixed Mode 只依赖浏览器 VAD 推进，不因缺少 Streaming ASR 而整体不可用。

## 本版修复（相对 v0.4.0-alpha.2）

- **时域 RMS 判停。** 浏览器 VAD 之前读取**频域**数据并除以 255，那不是振幅：非零环境
  噪声可以让一轮永远无法结束，安静房间也可能被当作说话。现在用 `getFloatTimeDomainData`
  计算线性 PCM RMS，并以本机噪声底（校准窗口内的安静样本）抬高起止阈值；残留非零噪声
  仍能正常判定回答结束并推进。
- **回答结束无法确认时按控制上限显式退出。** 一旦检测到疑似讲话，无回答超时不再适用；
  新增轮次上限，持续噪声/持续讲话/输入卡住时明确上报
  `observation_timeout`（`cannot_confirm_response_end`），关闭原因为
  `observation_end_unconfirmed`，**不记为回答完成**。
- **启动前能力预检，并由后端强制。** 新增
  `GET /api/voice-test/capabilities/{mode}`，返回该模式所需项与缺少项、浏览器需自行检查的
  能力，并明确标注**不发起付费探测**（`connectivity: not_probed`）。同一检查在
  `POST /api/voice-test/sessions/{id}/start` 与控制 socket 的 `start` 消息上强制生效：
  缺少项时拒绝启动、指名缺少项、**不发起任何 LLM/TTS/ASR 调用**，也不会先抓麦克风再等待。
  响应与日志都不包含凭据、服务地址或签名 URL。
- **不再静默降级。** `capture_mode=auto` 只解析为 Streaming ASR；缺少 Streaming ASR 时
  明确拒绝（而不是自动切到 `turn_file`）。整轮录音 + File ASR 只有在操作者在页面上**显式
  选择降级**时才使用，并在 UI、play 消息与执行记录中标注为降级。
- **文件降级路径真正做格式转换、转写提取与失败状态。** 浏览器上传的是它**实际录到的
  容器**（webm/ogg/mp4/wav），后端先校验容器签名与大小，再用 FFmpeg 解码为 canonical
  16 kHz mono PCM16 WAV 并做 canonical QA，然后才调用 File ASR；文本从归一化 segments
  提取。媒体非法、识别失败、空结果分别记录为 `invalid_audio` / `asr_failed`（HTTP 422/502），
  **不会包装成“成功的空 transcript”**，也不会推进下一轮。转写只能来自服务端捕获记录，
  浏览器自报的 transcript 不被信任。
- **迟到模型结果不再被播放。** 停止后若模型调用仍在飞行，其结果只作为供应商侧证据记录，
  不会合成 TTS、不会打开新一轮、不会播放。
- **Fixed Mode 只在需要合成时才要求 TTS。** 已有可用音频时复用资产，不要求 ASR 或 LLM；
  只有需要生成新音频时才检查 TTS。浏览器麦克风/连续采集/录音能力由页面单独检查。
- **配置变更即时可见。** 保存模型配置后，语音测试的预检与下一轮运行使用新配置，而不是
  继续使用进程内旧快照。

## 已验证范围（不要读成更多）

| 层级 | 状态 |
| --- | --- |
| 软件（单元/集成，真实 HTTP + WebSocket） | 已运行并通过（含能力预检强制、上传状态机、空/失败/非法媒体路径） |
| 受控浏览器（真实页面 + 合成麦克风 + 脚本化供应商） | 已运行并通过（A～E 定向验收，见下） |
| 候选镜像内运行 | 已运行并通过（镜像内启动各能力档位的受控服务，页面与路由来自镜像） |
| 真实云 Streaming ASR / File ASR | **未尝试**（无凭据） |
| 真实扬声器、真实麦克风、实体 AI 设备 | **未尝试** |
| 真实标签契约、预算与 Coverage、Barge-in | **尚未实现** |

定向验收（每项都在同一候选提交、同一候选镜像上运行）：

- **A 缺 ASR**：TTS/LLM 就绪、缺少 ASR 时，页面在抓麦克风之前拒绝启动；HTTP start 返回
  409、控制 socket 返回 `blocked`，两条路径都无法绕过；该会话 `provider_calls` 全为 0，
  执行记录只有 `session_start_refused`，没有 `play_issued`。
- **B 实时不被文件条件阻塞**：只有 Streaming ASR、完全没有 File ASR（因此也没有 Signed URL
  发布配置）时预检通过；页面走实时 Streaming ASR，无上传、无文件识别、无静默切换。
- **C 固定模式噪声场景**：真实页面使用修正后的时域判据；残留非零噪声仍能结束并推进；
  持续噪声按轮次上限显式退出且不伪造回答；停止 / 迟到事件 / 取消清理回归保持通过。
- **D 文件降级失败处理**：真实浏览器录音先解码转换为 canonical WAV 才进入 File ASR
  （脚本化识别器收到的输入为 16 kHz / mono / PCM16）；非法媒体、识别失败与空结果分别处理，
  失败不推进下一轮。
- **E 正向自由多轮**：受控供应商下连续三轮经真实页面、采集、传输、识别结果、Agent 上下文
  与播放完成；未手工伪造完成事件。

## 已知限制

- 上述浏览器验收使用**合成麦克风**（页面内可控振荡器）与**脚本化供应商**（测试替身），
  不是真实声场、真实云服务或实体设备证据。
- 预检只判断“用途已配置且适配器可用”，**不发起付费探测**，因此**配置存在不等于服务已连通**；
  真实鉴权/网络失败仍在真实调用时记录。
- 环境噪声底校准是**控制判据**，不是声学测量；VAD 只报告“疑似回答”，不识别说话人、
  不测量正式响应时延。
- 真实云 Streaming ASR（火山等）与 File ASR（含 `AIVOICEBENCH_AUDIO_PUT_URL` /
  `AIVOICEBENCH_AUDIO_GET_URL` / `AIVOICEBENCH_AUDIO_HOST` 指向的**同一个对象**）在真实
  凭据下的调用**未尝试**；Signed URL 音频发布仍是 Recording Analysis 的 File ASR 前置，
  但**不是** Active Voice Test 的 Streaming ASR 前置。
- 预算、Coverage、Barge-in、真实标签契约与 M3 完整验收**尚未实现**；真实云与实体设备
  结论不能由本版预览替代。

## 升级与使用

- 本版继续以 **Pre-release** 发布，不接管稳定版 `Latest` 标识；`v0.3.2` 仍是正式稳定版。
- 使用方式与 `v0.4.0-alpha.2` 相同（`docs/releases/docker-compose.preview.yml` 与
  `docs/releases/start-aivoicebench-preview.ps1` 已同步到本版本）；已有数据卷不会被删除，
  启动脚本不会执行 `docker rm -f`、`docker volume rm`、`docker rmi` 或 `docker system prune`。
- 自由对话的观察方式在页面上显式选择：默认“实时 Streaming ASR（正式链路）”；“降级：整轮
  录音 + 文件识别”需要操作者主动选择，页面与执行记录都会标注它不是实时识别。
