# AIVoiceBench v0.5.0

This is the stable release. The supported delivery is a Docker backend plus Web UI; no Windows EXE or installer is provided. This release consolidates the already-merged feature work from PRs #82, #83, #86, #88, #89, and #90.

## Scope and evidence boundary

- Audio QA exposes reviewable measurement conditions and does not claim ASR quality or accuracy.
- Recording Artifact chains and derived provenance remain reviewable across restart.
- Provider and object-storage configuration use server-side providers.yaml / storage.yaml; long-lived credentials are resolved only from env/secret references.
- File ASR supports inline | object_storage | auto; large-file transport uses private object storage and short-lived Presigned GET URLs.
- Real recordings, real cloud File ASR, real devices, and Measurement Equivalence were 未尝试 in this release. M1, Judge/Findings, immutable manual revision, and the complete report workflow remain 未实现.

## Installation

Download the release assets and verify SHA256SUMS.txt, then run:

`powershell
.\start-aivoicebench-preview.ps1 -Port 8000
`

Or load and start manually:

`powershell
docker load -i .\aivoicebench-v0.5.0.tar.gz
docker compose -f .\docker-compose.preview.yml up -d
`

Open http://127.0.0.1:8000. The launcher does not delete existing containers, images, or volumes.

## Cloud ASR prerequisites

The signed-URL compatibility path requires AIVOICEBENCH_AUDIO_PUT_URL, AIVOICEBENCH_AUDIO_GET_URL, and AIVOICEBENCH_AUDIO_HOST. The PUT and GET URLs must address 同一个对象; these variables are optional for local import and evidence workflows.

## Release verification

The formal release workflow builds from the merged main commit, verifies the tag, application version, and this versioned notes file, then runs Docker smoke, archive reload, fixed-dialogue, browser, and integration acceptance before creating the Release assets.

## 已知限制

- The default deployment is intended for a trusted single user on localhost; remote access needs authentication and TLS termination.
- Without cloud ASR / LLM credentials, local import and evidence workflows remain available, while cloud recognition and semantic role proposals are unavailable.
- Software and container verification do not constitute real-device acoustic measurement or Measurement Equivalence acceptance.
