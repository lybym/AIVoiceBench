## 相对 v0.4.0-alpha.5 的两处修复

- **会话停止后不再显示迟到转写。** 真实现象：`max_turns=3`、`on_no_response=pause` 时，第三轮触发
  `no_response_timeout`，服务端 session 已 `stopped`、执行记录已把该轮固定为 `no_response`，
  但网页仍把迟到的识别结果标成 **“设备（确认）：…”**。两侧都已修好：
  - 前端：设备文本行只在“当前正在观察的那一轮”更新；运行已结束/已取消、turn 不匹配、
    或服务端标记为 stale 的消息一律不写入该行，改为在自由对话日志中记为
    “已忽略迟到识别结果（原因；会话 …/轮次 …）”；会话以 `stopped` / `failed` 结束时清空该行
    （正常 `complete` 结束则保留最后一轮已确认的回答）。
  - 后端：capture 只有在“会话在运行 **且** 该轮仍在等待观察”时才算当前；此后到达的 Provider 事件
    **不写入该轮转写、不写入执行记录、不设置 capture 最终文本**，而是作为有界、显式标注的
    `stale` 诊断保留（带 session / turn / 原因），并以 `stale_transcript`（`ignored=true`）告知页面。
    `capture_result` 现在也带 `stale` / `stale_reason`。
- **`max_turns` 是严格整数契约**（同 alpha.5，此处一并列出以便测试）：只接受原生 JSON 整数且必须在
  `1..50`；`1.0`、`1.5`、`true`、`false`、`"3"`、`null` 一律以 HTTP 400 拒绝，不再被静默转换成 1/0 轮。

`max_turns=N` 的含义仍是**完整 N 轮**：第 N 个回答被观察并关闭之后，会话才以 `complete(max_turns)`
结束，不生成第 N+1 问、不再调用 LLM/TTS。

## 证据边界

- 迟到/控制层的时间戳**不是**声学测量证据；Streaming ASR 结果仍是 **Control Evidence**，
  不是 Measurement Evidence；
- 失败（`asr_no_final`、超时、无回答）**不是**回答，也不会被包装成“成功的空转写”；
- partial 不触发下一轮；不发明缺失的最终文本；
- 浏览器验收使用**合成麦克风**与**脚本化供应商**，不是真实声场、真实云服务或实体设备证据；
- 本版是**未合并候选分支构建的 Pre-release**，不是 main 发布。

## 已知限制

- 上述**浏览器**验收使用合成麦克风（页面内可控振荡器）与脚本化供应商（测试替身），
  真实扬声器、真实麦克风与实体 AI 设备的声学测量**未尝试**；
- Recording Analysis（导入录音 → File ASR → 时间戳转写 → 指标/事件）的**正式验收尚未完成**；
- 预检只判断“用途已配置且适配器可用”，**不发起付费探测**：配置存在不等于服务已连通；
- VAD 只报告“疑似回答”，不识别说话人、不测量正式响应时延；
- `provider_calls` 是会话级审计（`GET /api/voice-test/sessions/{id}`），**不在**持久化的
  `execution-record.json` 内；迟到事件同样是会话级 `stale_streaming_events` 诊断，
  按设计**不进入**执行记录（这样已结束轮次的记录不会被迟到消息改写）；
- 最后一轮若**没有**可用转写且 `on_no_response=pause`（默认），会话按既有策略记为 `stopped`
  （`no_device_transcript…`）而不是 `completed`；
- 预算、Coverage、Barge-in、真实标签契约与 M3 完整验收**尚未实现**；
- 本版预览**不包含**任何 Secret、真实用户录音或个人报告。

## 云 ASR 前置条件（Recording Analysis 的 File ASR）

三个变量必须**同时**设置，`AIVOICEBENCH_AUDIO_PUT_URL` 与 `AIVOICEBENCH_AUDIO_GET_URL` 必须指向
**同一个对象**，`AIVOICEBENCH_AUDIO_HOST` 必须与两者 hostname 一致：
`AIVOICEBENCH_AUDIO_PUT_URL`、`AIVOICEBENCH_AUDIO_GET_URL`、`AIVOICEBENCH_AUDIO_HOST`。
这些签名 URL 通常需要在对象存储/网关侧预先签发，无法仅在网页内完成。
（Streaming ASR 不需要它们。）

## 升级与使用

- 本版以 **Pre-release** 发布，不接管稳定版 `Latest` 标识；`v0.3.2` 仍是正式稳定版。
- 使用方式与 `v0.4.0-alpha.5` 相同：`docker-compose.preview.yml` 与
  `start-aivoicebench-preview.ps1` 已同步到本版本；已有数据卷不会被删除，
  启动脚本不会执行 `docker rm -f`、`docker volume rm`、`docker rmi` 或 `docker system prune`。
- 重新安装：下载本 Release 的 `aivoicebench-v0.4.0-alpha.6.tar.gz` 与启动脚本/Compose 到同一目录，
  先按 `SHA256SUMS.txt` 校验，再运行 `.\start-aivoicebench-preview.ps1`
  （默认 `127.0.0.1:8000`，自动 `docker load` 并校验镜像内版本），或
  `docker compose -f docker-compose.preview.yml up -d`。
- 测试建议路径：自由对话 → 观察方式选“实时 Streaming ASR” → 「最大轮次」填 3 →
  前两轮正常回答，第三轮**保持安静**直到控制上限；此时页面应显示“已停止：未观察到设备回答”，
  且**不出现**任何“设备（确认）”文本。
