## 本候选版相对 rc.3 的新增修复（来自 PR #114 / Issue #113）

v0.6.0-rc.3 的实机端到端测试记录了四项发现（[Issue #113](https://github.com/lybym/AIVoiceBench/issues/113)）；其中三项真实缺陷由 [PR #114](https://github.com/lybym/AIVoiceBench/pull/114) 修复，第四项是该录音自身的证据限制（见已知限制），按证据优先策略保持原样：

- **自由语音对话每轮推进有界且可解释（F021/F023）。** 修复"流式采集正常结束但会话停在首轮、无任何可见原因"的竞态：结果等待改为在发送 `capture_stopped` 后计时（服务端 drain 上限 + 余量），不再从采集打开时起算；服务端对在飞的 finalisation 做有界等待；超时显式记为 `capture_finalisation_timeout` 失败并关闭该轮，绝不记成设备回答；会话快照公开 `progress{phase, turn_id, reason_code, reason}`，让"在等待什么"可见。
- **人工角色确认保存改为可跟踪的异步操作（F012/F017）。** `POST /api/runs/{run_id}/role-review` 返回 `202 {operation_id, poll_url, phases}`，重建在独立线程执行；新增 `GET /api/runs/{run_id}/role-review/operations[/{operation_id}]`；拒绝码按 `run_locked` / `operation_in_progress` / `insufficient_evidence` / `internal_error` / `interrupted` 等区分并带 `retryable` 标记；操作记录在任何工作开始前落盘，带阶段、心跳、耗时，可跨重启查询；每次重建写结构化日志（`run_id`/`analysis_id`/`operation_id`/`phase`/`elapsed_ms`/`error_code`），不回显异常原文。
- **分析页统计口径与完成语义分列（F013/F014）。** 聚类数按 `speaker_id` 去重统计，不再把语音片段条数显示成"说话人聚类"；`complete_review` 的表述改为"人工角色决策已完成"，下游证据不足导致的指标弃权单独陈述，不再被读成"指标将完整生成"的承诺。

## 证据边界

- 软件 fixture、脚本化 Provider、合成麦克风与受控音频只证明有限的软件/契约行为，不是实体设备声学测量；本版所有 Feature PR 仅 `software_verified`。
- 失败、空 final、超时与无回答不会被包装成成功结果；证据不足时输出 `unknown`、`needs_review` 或 `insufficient_evidence`。
- 声学边界与 ASR speaker span 保持为相互独立的证据，对齐结果显式保留未匹配、冲突与未知状态。
- 角色归因只来自用户人工确认；未完成确认时 role-dependent Turns、Timeline、Metrics 与正式报告保持 `awaiting_role_review` / `insufficient_evidence`。
- TTS 事件一律为 Control Evidence（`evidence_scope: control_evidence`），不进入 Measurement Plane；流式链路失败不会静默回退到 HTTP SSE 或单向 WS。
- Release 不包含 Secret、真实用户录音或个人报告；长期凭据只在后端通过 env/secret reference 解析。

## 云 ASR 前置条件

签名 URL 兼容路径需要同时设置 `AIVOICEBENCH_AUDIO_PUT_URL`、`AIVOICEBENCH_AUDIO_GET_URL` 与 `AIVOICEBENCH_AUDIO_HOST`；PUT 与 GET 必须指向**同一个对象**，`AIVOICEBENCH_AUDIO_HOST` 必须与两者的 hostname 一致。这些变量对本地导入与证据工作流是可选的；未配置时云转写与说话人标签不可用。

## 安装与启动

下载本 Release 的全部附件，先用 `SHA256SUMS.txt` 校验，再启动：

```powershell
.\start-aivoicebench-preview.ps1 -Port 8000
```

或手动加载：

```powershell
docker load -i .\aivoicebench-v0.6.0-rc.4.tar.gz
docker compose -f .\docker-compose.preview.yml up -d
```

访问 http://127.0.0.1:8000。预览 Compose 与启动脚本只绑定 `127.0.0.1`，且不会删除既有容器、镜像或数据卷。

## 迁移与兼容

- 本版**不需要数据迁移**：既有 Run 数据、Artifact 与报告保持可读。PR #114 未改动任何 `schemas/**`、SQLite 表或既有 schema 定义（`speaker-role-review` / `speaker-role-mapping`、`role-review.json`、revision 不可变性保持 #95/#99 的定义）。
- **API 行为变化（需要知悉）：** `POST /api/runs/{run_id}/role-review` 由长时同步请求（200/409）改为 **202 Accepted + `operation_id` + `poll_url` + 阶段进度**的异步契约，拒绝码可区分且带 `retryable` 标记；新增 `GET /api/runs/{run_id}/role-review/operations[/{operation_id}]`。登记见 [contract versions](07-contract-versions.md)；Web 前端已同步改为轮询进度并跟踪在跑操作。直接调用该 API 的外部脚本需要跟随新契约。
- **行为变化（需要知悉）：** 自由语音对话中设备回答较慢时，该轮现在会等待在飞的识别 finalisation（有界），超时以 `capture_finalisation_timeout` 显式失败并关闭该轮——不再无声停在首轮；会话快照新增 `progress` 字段。
- **行为变化（需要知悉）：** 分析页聚类统计按 `speaker_id` 去重；"人工角色决策已完成"与"下游证据不足，指标已弃权"分列陈述。
- 沿用 rc.2 的配置/资产变化：新 WS TTS 协议拒绝 `format` / `encoding`（显式迁移提示），legacy HTTP SSE profile 仍可加载；新链路 Stimulus 为 MP3（legacy `.wav` 仍可读）。
