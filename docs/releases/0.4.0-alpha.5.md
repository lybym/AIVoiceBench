## 本版背景

- **`v0.4.0-alpha.4` 之后的 main 已包含 PR #73**（`fix: WSS streaming ASR profiles + accept a
  normal provider close after a definite final`）：火山引擎「流式语音识别 2.0」的 `wss://` 端点

  而是作为**独立的真实终止证据**记录（`terminated` / `termination_basis=provider_normal_close`
  / `close_code`），`saw_last_package` 依旧只表示 Provider 是否真的返回了文档中的
  `is_last_package` 字段。该修复**已合并到 main**，不属于本候选分支独有的内容。
- **本候选分支（PR #75）在此之上修复自由对话的轮次语义与输入契约。**

## 本版修复（相对已合并的 main）

- **`max_turns` 是完整轮次预算。** `max_turns=N` 现在表示完整执行 N 个平台轮次：
  Question → Playback → Device Observation → Streaming ASR final / 显式失败 →
  Capture Finalization → Turn Closure。第 N 个设备回答被观察并关闭**之后**，会话才以
  `complete(max_turns)` 结束；不再调用 LLM/TTS 生成第 N+1 问、不再发出第 N+1 次 `play`、
  `awaiting_turn_id=null`，最后一轮 Platform Turn 与 Device Turn 均关闭，最终 transcript /
  capture / provider audit / execution events 全部保留。
  此前实现把「已提问数」当成「已完成轮次数」，在第 N 次 `play` 之后立即结束并关闭该 Turn，
  导致第 N 个回答无法观察（真实复验中只能配成 `max_turns=N+1` 规避）。
- **`max_turns` 严格整数校验。** 只接受原生 JSON/Python `int`，且必须在 `1..50`：
  `1.0`、`1.5`、`true`、`false`、`"3"`、`null` 与越界值一律以既有风格的 HTTP 400 拒绝
  （`bool` 是 `int` 子类、`int(1.5)` 会截断，因此不做类型转换）。页面传入正常整数时的行为不变。
- **最后一轮按既有策略明确收尾。** 最后一轮出现 final transcript、`asr_no_final`、no response、
  Provider failure、用户停止或浏览器断开时都不会挂起；自由模式 VAD 超时 + `continue` 策略
  此前会停住不再继续，现在会按策略问下一题、预算用尽时明确结束。
- **已结束的运行不被改写。** `completed` / `stopped` / `failed` 不会被迟到的停止、断线或
  重复消息改写，也不会重复关闭 Turn。
- **发布元数据与镜像可追溯。** Dockerfile 新增 `org.opencontainers.image.revision`
  （由 `GIT_REVISION` 构建参数注入），发布镜像因此可追溯到它的发布候选 commit。

### 真实云 Streaming ASR 的证据边界

真实云端复验使用**已经配置在本地安全存储中的凭据**，端点为火山引擎流式语音识别 2.0
（优化端点、`resource_id=volc.seedasr.sauc.duration`、`model_name=bigmodel`），
`capture_mode` 协商为 `streaming`：

- 输入是**受控音频**：真实 TTS 合成的语音经**真实二进制音频通道**推入，
  **不是**物理设备、也不是浏览器麦克风的声学测量；
- Streaming ASR 结果仍是 **Control Evidence**，不是 Measurement Evidence；
- Provider 时间戳**不是** acoustic ground truth，未被用作正式声学时间真值；
- Provider 的自然结束仍保留真实字段（`termination_basis=provider_normal_close`、
  `close_code=1000`、`saw_last_package=false`），**没有伪造** `is_last_package`；
- 空/失败结果（`asr_no_final` 等）仍记为失败，**不会**被当作回答，也不发明缺失的最终文本。

## 已知限制

- 上述**浏览器**验收使用合成麦克风（页面内可控振荡器）与脚本化供应商（测试替身），
  不是真实声场、真实云服务或实体设备证据；**真实扬声器、真实麦克风与实体 AI 设备的
  声学测量未尝试**，也不能由本预览替代。
- Recording Analysis（导入录音 → File ASR → 时间戳转写 → 指标/事件）的**正式验收尚未完成**；
  本版不改变其证据链、指标契约与受众范围。
- 预检只判断“用途已配置且适配器可用”，**不发起付费探测**：配置存在不等于服务已连通，
  真实鉴权/网络失败仍在真实调用时记录。
- VAD 只报告“疑似回答”，不识别说话人、不测量正式响应时延；环境噪声底是控制判据，
  不是声学测量。
- `provider_calls`（会话级调用审计）通过 `GET /api/voice-test/sessions/{id}` 暴露，
  **不在**持久化的 `execution-record.json` 内；重启后不随记录保留。
- 最后一轮若**没有**可用转写且 `on_no_response=pause`（默认），会话按既有策略记为
  `stopped`（`no_device_transcript…`）而不是 `completed`——这是“无回答按会话策略处置”的
  既有语义，本版只保证它明确收尾、不挂起。
- 预算、Coverage、Barge-in、真实标签契约与 M3 完整验收**尚未实现**。
- 本版预览**不包含**任何 Secret、真实用户录音或个人报告；发布附件只有镜像归档、校验文件、
  启动脚本、Compose 文件与本说明。

## 云 ASR 前置条件（Recording Analysis 的 File ASR）

File ASR 的签名 URL 音频发布仍是 Recording Analysis 的前置条件（**不是** Active Voice Test 的
Streaming ASR 前置）。三个变量必须**同时**设置，`AIVOICEBENCH_AUDIO_PUT_URL` 与
`AIVOICEBENCH_AUDIO_GET_URL` 必须指向**同一个对象**，`AIVOICEBENCH_AUDIO_HOST` 必须与两者的
hostname 一致：`AIVOICEBENCH_AUDIO_PUT_URL`、`AIVOICEBENCH_AUDIO_GET_URL`、
`AIVOICEBENCH_AUDIO_HOST`。这些签名 URL 通常需要在对象存储/网关侧预先签发，无法仅在网页内完成。

## 升级与使用

- 本版以 **Pre-release** 发布，不接管稳定版 `Latest` 标识；`v0.3.2` 仍是正式稳定版。
- 使用方式与 `v0.4.0-alpha.4` 相同：`docker-compose.preview.yml` 与
  `start-aivoicebench-preview.ps1` 已同步到本版本；已有数据卷不会被删除，
  启动脚本不会执行 `docker rm -f`、`docker volume rm`、`docker rmi` 或 `docker system prune`。
- 自由对话的观察方式在页面上显式选择：默认“实时 Streaming ASR（正式链路）”；“降级：整轮
  录音 + 文件识别”需要操作者主动选择，页面与执行记录都会标注它不是实时识别。
- 「最大轮次」框里填 N，就会完整跑完 N 轮（含第 N 轮的回答），随后以 `complete(max_turns)` 结束。
