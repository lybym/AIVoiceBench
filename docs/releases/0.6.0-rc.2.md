# AIVoiceBench v0.6.0-rc.2（Release Candidate · 预览版）

**本版本是 Release Candidate（Pre-release，rc.2），不是稳定发布，不接管稳定版的 `Latest` 标识。** 它由 `main` HEAD `8dd2e49a12b5022f7b82b7e540bd00c6540a413d` 切出的发布分支 `release/v0.6.0` 准备，并由官方 `release.yml` workflow 从该分支的当前 HEAD 构建；稳定版 `v0.5.0` 仍是当前正式发布版本。本版只做版本与发布元数据收敛，**不实现新功能**：下列能力全部来自已合并到 `main` 的 Feature PR，且只达到 `software_verified`，真实录音/真实设备/Measurement Equivalence 验收状态不因本次候选版发布而升级。

## 证据边界

- 软件 fixture、脚本化 Provider、合成麦克风与受控音频只证明有限的软件/契约行为，不是实体设备声学测量；本版所有 Feature PR 仅 `software_verified`。
- 失败、空 final、超时与无回答不会被包装成成功结果；证据不足时输出 `unknown`、`needs_review` 或 `insufficient_evidence`。
- 声学边界与 ASR speaker span 保持为相互独立的证据，对齐结果显式保留未匹配、冲突与未知状态。
- 角色归因只来自用户人工确认；未完成确认时 role-dependent Turns、Timeline、Metrics 与正式报告保持 `awaiting_role_review` / `insufficient_evidence`。
- TTS 事件一律为 Control Evidence（`evidence_scope: control_evidence`），不进入 Measurement Plane；流式链路失败不会静默回退到 HTTP SSE 或单向 WS。
- Release 不包含 Secret、真实用户录音或个人报告；长期凭据只在后端通过 env/secret reference 解析。

## 云 ASR 前置条件

签名 URL 兼容路径需要同时设置 `AIVOICEBENCH_AUDIO_PUT_URL`、`AIVOICEBENCH_AUDIO_GET_URL` 与 `AIVOICEBENCH_AUDIO_HOST`；PUT 与 GET 必须指向**同一个对象**，`AIVOICEBENCH_AUDIO_HOST` 必须与两者的 hostname 一致。这些变量对本地导入与证据工作流是可选的；未配置时云转写与说话人标签不可用。

## 安装与启动

下载本 Release 的全部附件，先用 `SHA256SUMS.txt` 校验，再启动：

```powershell
.\start-aivoicebench-preview.ps1 -Port 8000
```

或手动加载：

```powershell

docker compose -f .\docker-compose.preview.yml up -d
```

访问 http://127.0.0.1:8000。预览 Compose 与启动脚本只绑定 `127.0.0.1`，且不会删除既有容器、镜像或数据卷。

## 迁移与兼容

- 本版**不需要数据迁移**：既有 Run 数据、Artifact 与报告保持可读，外置 `providers.yaml` / `storage.yaml` 与 SQLite legacy 兼容层不变；PR #109 未改动任何 `schemas/**` 或 SQLite 表。
- **行为变化（需要知悉）**：角色相关的分析现在必须在复核面完成人工角色确认后才会继续；未确认时 Run 保持 `awaiting_role_review`，这是产品约束的确定性实现，不是故障。
- **行为变化（需要知悉）**：无法计算的指标现在会带计数与原因显式说明，而不再以空值静默呈现。读取旧 Run 时可能看到此前未出现的缺口说明。
- **配置变化（需要知悉，opt-in）**：新的 WS protocol（`volcengine_tts_ws` / `volcengine_tts_ws_bidirectional`）不再接受 `format` / `encoding` 配置项，声明 `format: wav` 会**显式报错并给出迁移提示**，而不是被静默忽略；`pitch` 在单向 profile 被拒绝，endpoint 必须与所声明的 protocol 一致。遗留的 `volcengine_tts` HTTP SSE profile **仍可原样加载**（仍默认 `format=wav`），因此现有部署不因升级而中断，迁移是按 profile 的显式选择。
- **资产容器变化（需要知悉）**：新 WS 链路的 Stimulus 为 **MP3**，SHA-256 与 sample metadata 记录在 provider 返回值与 TTS sidecar 审计中；音频端点按真实容器返回 `audio/mpeg`（legacy `.wav` 仍可读）。既有 Run 资产不会被改写。

## 已知限制

- **M1 尚未通过。** `docs/prd/acceptance-status.md` 明确写明 “M1 尚未通过”：授权的真实 5–20 分钟录音、真实云 File ASR 与 speaker separation、人工标注/复核、完整 Judge/Findings 报告链与真实录音验收仍未闭环。本版不声明 `real_recording_verified`、`real_cloud_verified`、`real_device` 或 `measurement_equivalence_verified`。
- **#98 只完成了 provider 侧切片。** 已合入的是 V3 WS codec/adapter、`tts`/`streaming_tts` route 拆分、MP3 冻结 Stimulus 与失败分类；**尚未实现**浏览器端 MP3 streaming playback、Free 的 TTS audio channel/event 契约、上层 turn 编排在 turn 改变/run stop/barge-in 时调用 `cancel()`，以及 LLM streaming token 输出（Run snapshot 记 `streaming_tts_wiring = adapter_ready_no_consumer`）。M2/M3 不得被读作完成。
- **真实火山 V3 云调用未尝试。** 本环境无真实 credential 与计费授权，`real_cloud_call` 记为 `not_attempted`；单向请求时序（不等 `SessionStarted`）与 audio-only 帧布局仍为未验证假设，首次真实调用可能失败。
- **PR #108 的 Gate 检查器只是工具，不等于 M1 通过。** 它只能证明记录内的声明摘要与本地文件一致、声明之间互相授权，不能证明某个声明样本确实是授权真实录音；区间与来源属于只能与记录自身对账的条件。
- **真实云调用与真实 TOS 路径未尝试。** 火山 Seed ASR 真实调用、speaker separation 质量与对象存储真实路径仍需独立真实验收（#22、#85）。
- **#85、#98、#74、#9 仍为 Open。** #74（M3 `max_turns` 计数）与 #9（M2 Frozen Golden Voice）未实现。
- **尚未实现 / 未尝试的里程碑能力。** Active Measurement 正式 Pipeline（F025）、Execution/Analysis Run 自动关联（F024）、Measurement Equivalence（F026）、Compare 与 Frozen Golden Voice（F018–F019）、Streaming ASR（M3）、受控 Free Test Agent（M3）仍为 `planned`；TEN VAD 的许可证审查未完成前不视为依赖验收完成。
- **F004–F009 仍为 `partial`。** 编排、File ASR、归属、Turn/EventTimeline 与确定性指标的必要闭环仍缺失。PRD-F020/F021 与 F015/F016 因 #98 未闭环保持 `partial`。
- **契约版本登记边界。** PR #109 未改 `schemas/**`，也没有新增 SQLite 表，因此没有新增 schema 版本。Run snapshot 新增的持久字段（`streaming_tts_transport`、`streaming_tts_format`、`streaming_tts_wiring`、`streaming_tts_fallback_policy`）由 `aivoicebench/model_settings.py` 在捕获 Run snapshot 时写入，并由 `tests/test_tts_v3_websocket.py` 断言；文档层面只有相关背景说明——流式链路失败不静默 fallback 见 [Active TTS](28-active-tts.md) §4，`tts` / `streaming_tts` 两条 route 的协议配置契约见 `config/providers.example.yaml`。这些字段目前**尚未**在 [contract versions](07-contract-versions.md) 登记，本版把它作为后续跟进项如实披露，而不是已闭合。
- **默认分支基线。** 本候选版刷新了发布分支上的 `docs/PRD.md` `main_baseline` 与 Roadmap 基线；默认分支上的同名基线在 #109 合并后仍待同步。
