# AIVoiceBench v0.4.0

`v0.4.0` 是面向 Docker 后端与 Web UI 的正式版本。它以 `v0.4.0-alpha.6` 为候选基线，收敛自由对话 Streaming ASR 的完整轮次与迟到结果隔离、录音导入分析基础、可选语义角色提议，以及模块化产品需求文档。Windows 用户通过浏览器使用 Web UI，不提供 Windows EXE 或安装包。

## 本版内容

- **自由对话轮次可靠性。** `max_turns=N` 表示完整 N 轮；第 N 轮回答观察、capture 收尾和 Turn 关闭后才结束，不产生第 N+1 次 LLM/TTS/play。`max_turns` 只接受 `1..50` 的原生 JSON 整数。
- **迟到转写隔离。** 会话停止、轮次关闭或 turn 不匹配后到达的 Streaming ASR 结果不会写入确认回答或执行记录；它作为带原因的 `stale_transcript` 诊断保留。无回答仍明确显示为停止/失败，不伪装成回答。
- **Recording Analysis 基础。** 保留 WAV/MP3/M4A 导入、原件与标准化资产、Hash/provenance、Audio QA、File ASR、说话人聚类、归属/fusion、Turn/EventTimeline 和确定性指标的分阶段账本。
- **可选语义角色提议。** 对尚无显式角色证据的 speaker cluster，可由结构化模型输出提出 tester/device/unknown。提议必须引用既有 Evidence，始终 `needs_review`；显式/人工证据优先，冲突保留，失败或证据不足时保持 unknown。模型自报置信度不作为已校准准确率。
- **双正式 Measurement Pipeline 文档。** Active Measurement 与 Recording Analysis 各自保存独立声学原件，共享 Canonical EventTimeline、MetricResult 和指标定义。Control Evidence、Active Measurement Evidence 与 External Recording Evidence 不混用。
- **正式交付方式。** Release 提供 Docker 镜像归档、Compose、PowerShell 启动脚本与 SHA256SUMS；默认仅绑定 `127.0.0.1`，数据通过卷或宿主机目录持久化。

## 安装与启动

下载本 Release 的以下附件并放在同一目录：

- `aivoicebench-v0.4.0.tar.gz`
- `SHA256SUMS.txt`
- `docker-compose.preview.yml`
- `start-aivoicebench-preview.ps1`

先校验 SHA-256，再选择一种方式启动：

```powershell
.\start-aivoicebench-preview.ps1 -Port 8000
```

或：

```powershell
docker load -i .\aivoicebench-v0.4.0.tar.gz
docker compose -f .\docker-compose.preview.yml up -d
```

访问 <http://127.0.0.1:8000>。已有宿主机数据目录可继续将 `output` 挂载到容器 `/data/output`，将 `cache` 挂载到 `/data/cache`；启动脚本不会自动删除既有容器、镜像或数据卷。

## 验证范围

本地发布候选已通过 **585 项**单元/集成测试（11 项环境相关跳过）和 107 项发布/自由对话/语义归属定向测试。浏览器模块因本地环境未安装对应驱动而跳过，必须由 GitHub Release 工作流在候选镜像上完成。该工作流还会校验容器内版本与 revision、执行容器验收、导出归档并生成校验和。最终 tag、commit、浏览器/容器结果和镜像归档 SHA-256 以 GitHub Release 页面及附件为准。

## 证据边界

- 软件 fixture、脚本化 Provider、合成麦克风和受控音频只证明有限的软件、容器或浏览器行为，不是实体设备声学测量。
- Streaming ASR 结果属于 Control Evidence；Provider timestamp 不作为 acoustic ground truth。
- 语义角色输出是待复核机器提议，不等于真实 tester/device 识别通过。
- 失败、空 final、超时和无回答不会被包装成成功结果；证据不足时输出 unknown、needs_review 或 insufficient_evidence。
- Release 不包含 Secret、真实用户录音或个人报告。

## 已知限制

- Recording Analysis 的 5–20 分钟真实录音、真实云 File ASR、人工标注和完整报告验收尚未闭环，因此产品 M1 尚未宣称通过。
- 真实物理设备、真实扬声器/麦克风声场、Active Measurement Audio、Stimulus Alignment、Barge-in 正式测量与 Measurement Equivalence **未尝试或尚未实现**。
- Recording Analysis 使用真实云 File ASR 时，必须同时配置 `AIVOICEBENCH_AUDIO_PUT_URL`、`AIVOICEBENCH_AUDIO_GET_URL` 与 `AIVOICEBENCH_AUDIO_HOST`；PUT/GET 必须指向同一个对象，HOST 必须匹配 URL 的 hostname。这些签名 URL 需由对象存储或网关预先签发。
- 模型配置预检不发起付费连通探测；配置已保存不代表云服务一定可用。
- 普通 Web UI 尚无完整的 ASR 文本、角色、事件边界与 Turn 关联人工修订工作流。
- ImportRun 尚未执行完整 Judge/Findings；当前状态报告不能解释为设备通过。
- `provider_calls` 和迟到事件诊断属于会话级审计，未写入持久化 `execution-record.json`。
- 默认部署面向可信单用户 localhost；远程访问需要另行配置认证与 TLS 代理。

## 升级说明

从 `v0.4.0-alpha.6` 升级时可复用原 `/data/output` 数据。建议先备份宿主机数据目录或命名卷，再停止旧容器、加载新镜像并以相同挂载启动。不要把数据目录打包进镜像或提交到 Git。
