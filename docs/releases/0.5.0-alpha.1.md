# AIVoiceBench v0.5.0-alpha.1（预览版）

**这是一个预览版（Pre-release），不是稳定发布，也不是 M1/M2/M3 正式验收完成。** `v0.5.0-alpha.1` 由 `main`（HEAD `f47da0d`）切出的发布分支 `release/v0.5.0-alpha.1` 准备：应用版本、Docker `version` 标签、预览 Compose 与 Windows 启动脚本统一为 `0.5.0-alpha.1`。Pre-release 不接管稳定版 `Latest` 标识；`v0.4.0` 仍是当前正式稳定版。本版只做版本与发布元数据收敛，不实现新功能；下列能力均来自已合并到 `main` 的 Feature PR，且只达到 `software_verified`，真实录音/真实设备/Measurement Equivalence 验收均未尝试。

## 相对 v0.4.0 的已合并能力（software_verified，非真实验收）

- **Audio QA 有效性条件（PR #86，Issue #21）。** `canonical_qa()` 不再输出未被消费的 `quality_gate: not_configured`，改为按测量事实发布 `conditions`（`decodable_canonical_audio`、`nonempty_signal`）；任何条件都不写成 pass/fail，也不声明识别质量或 ASR 准确率。Web Run 视图 `GET /api/runs/{run_id}` 新增 `audio_qa` 读视图，展示格式/时长/声道/采样率与逐条件依据，并明确标注不构成验收结论；重启/resume 后仍可读到同一 `audio_qa` 与 stage reason 且不重复调用 ASR。
- **录音 Artifact 链隔离与派生 provenance 加固（PR #89，Issue #21）。** 对录音导入的 Artifact 链与派生 provenance 进行隔离与加固，使派生产物显式引用其来源 provenance，跨重启可复核；软件测试覆盖该链路，真实录音验收不变。
- **Provider / 对象存储外置配置与 File ASR transport（PR #88 文档 + PR #90 实现，Issue #87）。** LLM/File ASR/Streaming ASR/TTS 的非敏感配置收敛到服务器侧外置 `providers.yaml`，对象存储参数收敛到独立 `storage.yaml`，Docker 只读挂载；长期密钥只通过 env/secret reference 解析，不写入配置文件、Git、浏览器或报告。File ASR 极速版实现 `inline | object_storage | auto`：默认 `auto`，小文件（初始阈值 15 MiB，可配置）使用 `audio.data` Base64 直传，不要求对象存储；大文件由 Backend 直接上传私有 TOS 并生成短期 Presigned GET 作为 `audio.url`，识别后清理并保留 lifecycle 兜底。SQLite model settings 与固定签名 URL 路径被标记为 legacy/待迁移兼容层，不再作为生产 source of truth。
- **文档收敛（PR #82、#83、#88）。** 记录 `v0.4.0` 正式发布证据、收敛远端 Browser Station 与可复用语音组件文档、外置 provider/storage 配置与 File ASR transport 文档；均为 docs-only，不改变代码或验收状态。

## 证据边界

- 软件 fixture、脚本化 Provider、合成麦克风和受控音频只证明有限的软件/契约行为，不是实体设备声学测量；本版所有 Feature PR 仅 `software_verified`。
- 失败、空 final、超时和无回答不会被包装成成功结果；证据不足时输出 `unknown`、`needs_review` 或 `insufficient_evidence`。
- Audio QA 条件只声明测量事实，不声明识别质量、ASR 准确率或测量准确率。
- 外置配置只接受 credential env reference，不接受 secret 值；presigned URL 只在内存传给 ASR provider，不写入 Run snapshot/report/log。
- Release 不包含 Secret、真实用户录音或个人报告。

## 迁移说明（#90 config-ownership migration）

- **外置配置文件。** 部署时将 `providers.yaml` 与 `storage.yaml` 放到服务器拥有的运行时路径（默认 `/etc/aivoicebench/`，可由 `AIVOICEBENCH_PROVIDERS_CONFIG`/`AIVOICEBENCH_STORAGE_CONFIG` 覆盖），Docker 只读挂载；长期密钥只通过 env/secret reference 解析，不写 YAML。
- **File ASR transport。** 默认 `auto`：小文件 inline Base64（不要求 Storage），大文件私有 TOS + 短期 Presigned GET。生产路径已迁离固定签名 URL。
- **legacy signed-URL 兼容（仍可读但非生产路径）。** 历史 Recording Analysis File ASR 依赖三个变量同时设置：`AIVOICEBENCH_AUDIO_PUT_URL` 与 `AIVOICEBENCH_AUDIO_GET_URL` 必须指向**同一个对象**，`AIVOICEBENCH_AUDIO_HOST` 必须与两者 hostname 一致；这些签名 URL 需在对象存储/网关侧预先签发。#90 已把生产路径迁离该机制，但在真实 TOS 路径于 main 线验证完成前，它仍作为 legacy/兼容路径文档保留，不得读成新 transport 已真实通过。
- **SQLite model settings。** 与外置配置不静默合并，冲突可审计；已有 Run 数据可继续读取，无需迁移数据。

## 安装与启动（预览）

本 PR 不附带镜像归档。镜像由后续 `release.yml`（manual dispatch，tag `v0.5.0-alpha.1`）构建后，从 GitHub Release 下载 `aivoicebench-v0.5.0-alpha.1.tar.gz`、`docker-compose.preview.yml`、`start-aivoicebench-preview.ps1` 与 `SHA256SUMS.txt`，先校验 SHA-256，再启动：

```powershell
.\start-aivoicebench-preview.ps1 -Port 8000
```

或：

```powershell
docker load -i .\aivoicebench-v0.5.0-alpha.1.tar.gz
docker compose -f .\docker-compose.preview.yml up -d
```

访问 <http://127.0.0.1:8000>。已有宿主机数据目录可继续挂载；启动脚本不会自动删除既有容器、镜像或数据卷。
