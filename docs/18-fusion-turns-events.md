# Speaker clustering / Attribution / Fusion / Events

2026-09-11 基线 main c612d36 / alpha.2；产品要求见 [PRD-F006～F009](PRD.md)。

ImportRun 分别登记 acoustic、diarization、attribution、fusion、turns、timeline、metrics。ASRNativeDiarizationProvider 复用已有 ASR 原生响应/Transcript 标签，不追加服务调用；需配置 ASR 与 diarization 路由。`partial` Transcript 中仍合法的 utterance/speaker labels 继续作为 evidence，gap 单独保留；缺标签则 insufficient_evidence，不按轮流发言补标签。

聚类与角色分开：speaker ID 按录音 Hash 隔离并保留 invocation/原生响应引用；不同录音的 speaker_0 不是同一身份。聚类 confidence 留空，角色默认 unknown。Recording Analysis 不调用 LLM 判断角色；用户在 Web 人工确认面板中逐个聚类标记 tester/device/unknown，保存为新的 AnalysisRevision 后才重跑 Attribution 及其下游。Gate 状态由每个 revision 发布的 `role-review.json` 记录（`awaiting_role_review` / `incomplete_review` / `complete_review`），修改 mapping 会再生成一份 revision 并显示 diff；实现见 [#95](https://github.com/lybym/AIVoiceBench/issues/95) 与 [role_review.py](../aivoicebench/role_review.py)。

跨聚类声学片段按边界拆分，重叠标签冲突以 ambiguous_overlap 弃权，不整段归给最大重叠者。拆分文本来自相应 ASR 区间，不把全文复制到每段；原始声学边界与 provider_utterance_estimate 分开记录，不把估计边界变成声学真值。

acoustic segment ↔ ASR speaker span 的对齐由独立确定性模块 [alignment.py](../aivoicebench/alignment.py) 计算，fusion 只物化它的结论，因此重叠规则只有一份实现。每个 acoustic segment 得到一个显式状态：`unmatched | single_cluster | multi_cluster | conflict`；匹配项保留双方区间、交集、有符号边界偏移、两个方向的重叠比例与聚类身份。诊断输出 `unmatched_acoustic_ms`、`unmatched_speaker_ms`、逐聚类 `coverage_ratio`、`low_energy` 分布与 `boundary_drift_ms`，全部带分母。对齐文档以 `speaker-alignment` artifact 登记（`alignment.json`）并校验独立 schema；它不含 `speaker_role`，不把匿名 cluster 映射成 tester/device。

2026-09-18 的诊断样本出现“ASR 有 cluster、84 个 acoustic segments 均无 cluster/role”的对齐缺口；[#94](https://github.com/lybym/AIVoiceBench/issues/94) 已按上述策略实现，指标不再空白但仍然弃权时，API `metrics_gap`、Run API/Web 与报告会给出原因与计数（未匹配时长、冲突片段数、low-energy 覆盖、角色未确认），而不是只显示空表。

角色资格**按区间判定**（[#115](https://github.com/lybym/AIVoiceBench/issues/115)）：有已确认 tester/device 角色的 fused segment 才进入 turns/responses 与 Timeline/指标，_timeline() 绑定 Run 身份。已确认角色的区间照常产生 Canonical Event 与合格 MetricResult；人工判定 `unknown`、尚无决定、聚类冲突或无 speaker span 覆盖的区间不产生任何角色相关事件，只保留其声学证据并各自发布一条显式 gap。整段录音都无可确认角色时仍为整体不足证据，原因写明具体 Gate（`awaiting_role_review`、`incomplete_review` 或“全部聚类被人工判为未知”）。`metrics_gap` 按真实状态分码：`roles_human_declared_unknown`（人工明确判定未知——这是已完成的决定，不表示指标已通过）、`roles_awaiting_human_decision`（尚无保存决定）、`segments_without_speaker_span`、`ambiguous_speaker_overlap`，`roles_not_confirmed` 只统计前三者中除“人工已判定未知”之外的片段。silence/timeout 只在两端区间角色都成立时成立，未归属片段两侧的空间不得当作 PRD-F008 的已观察窗口。完整旧/新回答语义关联、timeout 健康窗口和真实混音打断判定仍待验收。

Turn/Event 层不得把“部分证据”呈现成完整结论，[#24](https://github.com/lybym/AIVoiceBench/issues/24) 固定了以下语义：拆分后的每个 fused segment 拥有唯一 `segment_id`（原 `acoustic_segment_id` 保留来源，两段拆分前曾共用父 id，导致 turn 关联与 timeline `ev_map` 互相覆盖、事件引用了不覆盖自身的证据）；`turn_id`/`response_id` 按已生成 turn 的位置连续编号，设备先发言时不会缺号也不会重号；`build_turns` 继承 fused 文档的不完整状态与原因，只覆盖已确认角色子集时输出 `partial` 而非 `complete`；`detect_events` 在存在未确认角色片段时输出 `partial`（#115 起为区间级资格判定：未确认区间不再清空已确认区间的事件），`generate_timeline` 对任何非 `complete` 时间线写入 `gaps`——部分可归属时逐保留区间一条并给出所需证据（`new_human_role_decision` / `speaker_diarization_or_human_review` / `unambiguous_speaker_alignment` / `overlapping_speaker_span`），整体不可归属时保持一条整段录音 gap；声学时间证据只标注声学边界置信度，不再把角色归属或聚类置信度当作声学测量质量，拆分边来自 provider 估计时不发布声学置信度。非交替发言（同一角色连续两段、设备先发言）是显式测试场景，不假设轮流发言。依据与用例：[test_turns_events_attribution.py](../tests/test_turns_events_attribution.py)、[test_local_evidence_qualification.py](../tests/test_local_evidence_qualification.py)、契约决定见 [docs/07](07-contract-versions.md)。

Active Measurement 将通过独立 Online Event Producer 产生相同 Canonical Event 类型；它利用已知 Stimulus Reference 形成 tester evidence，而不是机械复用 `speaker_0/speaker_1` 角色映射。两条 Pipeline 的声学 Evidence ID/Artifact 必须不同，event producer/policy 进入 provenance；下游继续使用同一 Timeline/Metric 语义。单麦克风 overlap 的旧 response stop boundary 在 reference cancellation/AEC/source-aware evidence 就绪前保持 insufficient_evidence。

打断事件必须成对（Issue #10 修正）。`timeline_errors` 用 `interrupt_end → interrupt_start` 配对，`complete` 时间线上未闭合的 `interrupt_start` 会让整个 Timeline 无效——而无效 Timeline 会阻断所有下游消费者（PRD-M005 与 PRD-M006）。Issue #10 之前 `detect_events` 只发出 `interrupt_start`，因此真实打断录音会产生一个无法通过自身校验的 Timeline。现在每个 interrupting tester segment 发出成对的 `interrupt_start`（该段 `start_ms`）与 `interrupt_end`（该段 `end_ms`），两者都是 point event 且引用同一证据。

**打断事件的绑定约定（两套引擎，已明确边界）。** `detect_events` 把两个事件都绑到**被打断的** turn 与该 turn 的旧 `response_id`——这正是 Canonical Metric Engine（`metrics._barge_in_stop`，PRD-M005 under `definition_version` 4.0.0）消费的约定：它按 `turn_id` 分组事件、再用 `interrupt.response_id` 找被打断回答的 `device_speech_end`。`examples/timelines/barge-in.json` 使用的是另一套写法（`interrupt_start`/`interrupt_end` 绑到 interrupting turn 且 `response_id: null`），它是**旧引擎 `engine.evaluate` 的规范输入**——`tests/test_engine.py::test_barge_stops_old_response` 依赖该写法得到 200ms。两套约定服务两个不同引擎，谁消费哪一套以本节为准；把 legacy 示例改成 producer 约定会改变旧引擎结果（超出 #10 范围，需单独 Issue 决定），因此这里显式记录而不是静默统一。Canonical 路径的约定由 [test_barge_in_producer.py](../tests/test_barge_in_producer.py) 从真实 producer 输出固定（含 `turn_id`/`response_id` 绑定与 M005 值）。
